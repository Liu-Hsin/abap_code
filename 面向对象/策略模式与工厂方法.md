### 工厂方法模式（Factory Method）

| 工厂方法模式核心要素 | 代码对应实现                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------- |
| 产品接口       | `lf_cancel` 接口：定义了 `cancel_before_check`/`cancel_doc`/`save_log` 三个统一方法，是所有 “取消单据” 类的通用规范       |
| 具体产品类      | `lcl_cancel_so`/`lcl_cancel_dn`/`lcl_cancel_gi`/`lcl_cancel_bill`：实现 `lf_cancel` 接口，封装不同单据的取消逻辑 |
| 工厂类        | `lcl_factory` 类：通过 `create_handler_class` 类方法，根据 `iv_doc_type`（SO/DN/GI/BILL）创建对应单据的取消类实例       |
| 工厂方法       | `create_handler_class` 方法：接收单据类型参数，动态创建对应子类实例（`LCL_CANCEL_SO`/`LCL_CANCEL_DN`等），返回接口类型引用        |

```abap
* 工厂方法核心逻辑：根据单据类型动态创建对应取消类实例 
class lcl_factory implementation. 
	method create_handler_class. 
		data lv_object type char35. 
		lv_object = |LCL_CANCEL_{ iv_doc_type }|. " 拼接类名（SO/DN/GI/BILL） 
		try. 
			create object ro_handler type (lv_object). " 动态创建子类实例 
		catch cx_root into data(lo_error).

```
- 这里通过**动态类名创建对象**的方式，是 ABAP 中工厂方法模式的典型实现（替代硬编码`CASE`分支）；
- 返回值`ro_handler`是`lf_cancel`接口类型，保证了 “里氏替换原则”—— 无论创建哪种单据取消类，调用方都用统一的接口方法。
### 策略模式（Strategy）

| 策略模式核心要素 | 代码对应实现                                                                |
| -------- | --------------------------------------------------------------------- |
| 策略接口     | `lf_cancel` 接口：定义了 “取消单据” 的算法骨架（校验→取消→记录日志）                           |
| 具体策略类    | `lcl_cancel_so`/`lcl_cancel_dn`等：每个类是一种 “取消策略”，实现接口的具体逻辑              |
| 上下文类     | `lcl_main` 类：`cancel_doc` 方法中通过接口调用策略方法，封装策略的执行流程（校验→取消→日志），不关心具体策略实现 |
```abap
* 上下文类（lcl_main）执行策略的核心逻辑 
method cancel_doc. 
" 1. 通过工厂获取策略实例（接口类型） 
	lo_handel = lcl_factory=>create_handler_class( iv_doc_type = lv_doc_type ). 
" 2. 统一调用接口方法（策略执行） 
	es_return = lo_handel->cancel_before_check( iv_doc = iv_doc ). " 校验策略
	lo_handel->cancel_doc( iv_doc = iv_doc ). " 取消策略 
	lo_handel->save_log( is_log = es_return ). " 日志策略 
endmethod.
```
- **核心模式**：代码是**工厂方法模式**（通过工厂动态创建不同单据的取消类实例）+ **策略模式**（不同单据的取消逻辑作为可替换的策略）的组合；
- **核心价值**：
    
    - 工厂方法：封装了 “取消类实例的创建逻辑”，调用方无需知道具体类名；
    - 策略模式：封装了 “不同单据的取消算法”，实现了算法与执行流程的解耦；
    
- **模式本质**：工厂方法解决 “对象创建” 的问题，策略模式解决 “算法替换” 的问题，二者结合是 SAP 中处理多类型单据业务的最优解之一。
